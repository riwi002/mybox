## 深度优化 ssh_config_manager 选项3「配置当前账户仅密钥登录」

优化为 7 步交互式流程：

**Step 1 - 权限修复：** 自动修复 .ssh 目录 (700) 和 authorized_keys (600) 权限

**Step 2 - 密钥为空引导：** 当 authorized_keys 为空时，不再简单警告后放弃，而是提供交互式菜单：
- 选项1：粘贴已有公钥
- 选项2：自动生成新密钥对（ed25519 默认 / RSA 3072 可选）
- 选项0：返回

**Step 3 - 生效范围选择：**
- 全局生效（PasswordAuthentication no + PermitRootLogin no）：影响所有用户，同时禁止 root SSH 登录
- 仅当前用户（Match User 块）：只对当前用户生效，不影响其他用户

**Step 4 - 变更预览：** 操作前展示当前值 → 目标值的对照表，全局模式下明确标注 Root 登录也会被禁止；`PermitRootLogin=yes` 时橙色警告

**Step 5 - 写入配置：**
- 全局模式：修改 PasswordAuthentication + PubkeyAuthentication + PermitRootLogin no；参数不存在时追加
- 单用户模式：用行号精确删除旧 Match 块（避免 sed 正则 bug），再追加新 Match User 块（4 空格缩进）

**Step 6 - sshd -t 语法检查：** 写入后先检查语法，失败则阻止重启

**Step 7 - 重启确认：** 询问是否立即重启 SSH 服务

**其他改进：**
- 默认密钥类型改为 ed25519（RSA 3072 作为可选项）
- 用户名特殊字符转义（`_cur_user_esc`），避免 sed 正则 bug
- VNC 兜底提示：「如配置失误可通过腾讯云 VNC 控制台救援」
- 私钥生成后提示下载方式（scp/SFTP）
- 移除了 PermitEmptyPasswords、ChallengeResponseAuthentication 等非核心配置

## 修复 Git管理 选项11/12 的权限错误

**问题诊断：**
- 错误信息：`error: insufficient permission for adding an object to repository database .git/objects`
- 根本原因：`.git` 目录所有者是 root，但脚本以普通用户运行，`git add .` 无法写入 object 文件
- `git add` 失败后没有检测返回值，直接走到 `git commit`，commit 因暂存区为空而失败
- 提交失败提示「没有可提交的更改」是误导性的——真正原因是权限不足

**修复内容（选项11 提交全部文件 + 选项12 自定义提交）：**
1. `git add` 前检查 `.git` 目录所有者，如果不是当前用户则提示修复（`chown -R`）
2. `git add` 后检测返回值，失败则显示修复命令并终止
3. `git commit` 输出捕获到变量，失败时根据错误类型给出针对性提示：
   - `insufficient permission` → 提示 chown 修复
   - `nothing to commit` → 提示没有更改
   - `Error building trees` → 提示 git add 可能因权限失败
