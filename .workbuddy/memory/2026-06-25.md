## riwi.sh install 函数 sudo 支持 + 克隆仓库优化

用户反馈：普通用户下克隆仓库报 `Permission denied`（apt 装不了 git）和 `git: command not found`（git 没装就执行 git clone）。

### 问题根因
1. `install` 函数在普通用户下直接执行 `apt install`，没有 sudo 前缀，导致权限不足
2. `install git` 失败后没有检查 git 是否真的装上，直接执行 `git clone`，报 command not found

### 完成的改动

**1. install 函数加 sudo 前缀（668 行起）**
- 函数开头检测当前用户 sudo 权限：
  - root：不需要前缀
  - 免密 sudo（`sudo -n true`）：直接加 sudo
  - 在 sudo/wheel 组（需密码）：`sudo -v` 缓存密码后加 sudo
- 所有包管理器命令（dnf/yum/apt/apk/pacman/zypper/opkg/pkg）都加 `$_sudo_pfx` 前缀
- 影响范围：全脚本所有 `install xxx` 调用都受益（不止 git）

**2. 克隆仓库逻辑优化（23308 行起）**
- 先 `command -v git` 检测，没装才调 `install git`
- install 后再次检测 git 是否装上，没装就报错退出，不往下走
- 去掉「选择克隆方式」交互（之前让用户选普通/sudo 太啰嗦）
- 改为自动判断：目标父目录可写 → 普通克隆；不可写 → 自动检测 sudo 并验证密码
- sudo 克隆后自动 chown 属主回当前用户

### 验证
- bash -n 语法检查通过
- install 函数 sudo 检测逻辑正确（root/免密/需密码三路）
- 克隆逻辑：先装 git → 再检测 git → 再克隆，不会 command not found

## 双证启用后 SSH 拒绝登录 — 根因: Match 块清理用 whoami (03:33)

### 用户报错
- SSH 客户端: ecdsa-sha2-nistp256 私钥 `/Users/owen/Desktop/key/莱卡云/xin/key`
- 现象: `Authentication rejected`，启用双证后无法连接
- 关键: 用户 SSH 登录用普通用户（xin），不是 root

### 根因
`_ssh_clear_conflicting_auth()` 用 `whoami` 取当前用户清理 Match 块。
但用户是 `su -` 切到 root 跑脚本，`whoami` 返回 root，
导致 **xin 用户的 Match 块残留**（如 `AuthenticationMethods publickey`），
覆盖全局设置，公钥认证走不通，双证自然启用失败。

### 修复（riwi.sh 行 20597-20636）
1. `_ssh_clear_conflicting_auth`: 不再用 whoami，改为 awk 遍历**所有** Match 块，
   注释掉认证字段（AuthenticationMethods/KbdInteractive/ChallengeResponse/Password/Pubkey），
   保留 Match 块本身和无关字段（AllowTcpForwarding 等）
2. `_ssh_backup_configs`: 备份改为遍历所有可登录用户的 authorized_keys，
   不只备份 $HOME（whoami 的）
3. `_ssh_restore_backup`: 配套回滚所有用户的 authorized_keys

### awk Match 块边界
- sshd_config 的 Match 块: 从 Match 行到下一个 Match 行或 EOF
- awk 用 `in_match` 标志位，遇 Match 行置 1，不退出（直到下一个 Match 或 EOF）
- 用 END 块返回 cleaned 状态决定是否替换文件

- 验证: 全局字段保留、Match 内认证字段被注释、无关字段保留、两块都被处理 ✓
