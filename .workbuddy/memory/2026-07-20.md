## 取消/返回不再显示"操作完成"和"按任意键继续"
- 新增 `break_cancel()` 函数（L862）：只 clear，不显示"操作完成"/"按任意键继续..."
- 批量将取消/返回场景的 `break_end` 替换为 `break_cancel`，共 49 处 + 4 处重构
  - 单行模式：`yellow "已取消"; break_end; continue` → `break_cancel`
  - 多行模式：`yellow "已取消"` 下一行的 `break_end` → `break_cancel`
  - 4 处特殊重构：break_end 同时服务成功+取消两条路径的，将 break_end 移入成功分支，取消分支不加暂停
- `0)` 返回主菜单选项本来就不含 break_end，无需改动
- bash -n 语法检查通过
- 备份: riwi.sh.bak_cancel_breakend_20260720

## 子菜单 0) 返回时 break_end 修复（第二轮）
- 问题根因：16 个子菜单的 `0) break` 只跳出 while 循环，`esac` 后的 `break_end` 仍会执行
- 另有 1 处 `0) riwi ;;`（多行写法）同样的问题
- 修复：将这 17 处 `esac` 后的 `break_end` 替换为 `break_cancel`
- `0) return ;;` 的不需要改（return 直接退出函数，不会走到 break_end）
- `0) clear ; exit ;;` 不需要改（exit 直接退出脚本）
- bash -n 语法检查通过
- break_cancel 总数：67 处

## 子菜单 0) 返回时 break_end 修复（第三轮 - 多行写法遗漏）
- 第二轮只匹配了单行 `0) break ;;`，遗漏了 11 处多行写法 `0)\n break\n ;;`
- 修复位置：L10742, L10956, L17596, L17778, L21364, L21714, L22744, L23111, L23987, L24333, L25183
- 最终验证：ALL CLEAR，无任何 `0) break` → `break_end` 遗留
- bash -n 语法检查通过
- break_cancel 总数：78 处 | break_end: 279 处
- 备份: riwi.sh.bak_cancel_round3_20260720

## 主菜单 riwi_sh() break_end → break_cancel（最终修复）
- 问题根因：子菜单选 0 返回 → 函数返回 → riwi_sh 主菜单 esac 后的 break_end 执行 → 显示"操作完成"
- 之前只改了子菜单内部的 break_end，但主菜单 riwi_sh 的 break_end 是所有子菜单返回后的必经之路
- 新增 `_menu_returning` 全局变量 + break_end 内部判断（保留备用）
- 最终修复：riwi_sh 主菜单的 break_end 改为 break_cancel
  - 主菜单 while 循环本身有 clear + 重新显示菜单，不需要"操作完成"提示
  - 子菜单内部的 break_end 不受影响，正常操作后仍显示"操作完成"
- 备份: riwi.sh.bak_mainmenu_breakend_20260720
